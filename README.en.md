Double Love provides automated and standardized processing for production metadata. It supports offline use. Through batch processing and localization, it ensures seamless integration with Adobe Premiere, Silverstack, and DTG Slate to ensure metadata consistency. This effectively improves the efficiency of post-production workflows.

## ✨ Features

- 🎬 Film industry workflow support
- 📝 Intelligent metadata standardization
- ⚡ Zero-latency local processing
- 🧩 Seamless Adobe Premiere integration

## 🚀 Quick Start

### Basic Workflow

1. Script Supervision: Generate interactive logging sheets using DTG Slate
2. Data Management: Import logging data through Silverstack Lab
3. File Export: Generate Adobe Premiere Pro XML
4. Standardization: Process with Double Love for intelligent optimization

Example:
- Input xml: `UnitA_304_20250127.xml`
- Output xml: `UnitA_304_20250127_Double_LOVE.xml`

### Detailed Examples

#### File Naming Optimization
- Automatic formatting of scene, shot, and take numbers
- Auto-padding numbers with leading zeros
- Automatic case standardization
- Redundant underscore cleanup

#### Shot/Take Field Rules

- After whitespace is removed, `shot-take` must contain exactly one hyphen and two non-empty parts.
- Each part must contain at least one Unicode decimal digit; all other characters must be Unicode letters or numbers.
- Each numeric run is padded to two digits. Latin letters are lowercased; Chinese and other Unicode letters are preserved.
- `1A-1`, `B1-2`, and `1-2跑` are accepted and normalized. Punctuation or a part without a digit is skipped.

#### Clip Naming Convention

The processed clip names follow dynamic formats based on available data:

#### Naming Formats for Different Data Sources

1. **With Season + Episode data** (CSV contains both Season and Episode columns):
```
{season}_{episode}_{scene}_{shot}_{take}{camera}_{rating}
```

2. **Episode data only** (CSV contains only Episode column):
```
{episode}_{scene}_{shot}_{take}{camera}_{rating}
```

3. **No CSV data** (traditional format):
```
{scene}_{shot}_{take}{camera}_{rating}
```

#### Parameter Descriptions
- `season`: Season number (2 digits, e.g., 01)
- `episode`: Episode number (2 digits, e.g., 44)
- `scene`: Scene value kept for compatibility; numeric runs are padded to at least 3 digits (e.g., 026)
- `shot`: Shot part; Unicode letters/numbers, numeric runs padded to 2 digits (e.g., 01a)
- `take`: Take part; Unicode letters/numbers, numeric runs padded to 2 digits (e.g., 02跑)
- `camera`: Camera identifier (lowercase letter, e.g., d)
- `rating`: Rating (ok/kp/ng)

#### Rating Processing
- `Circle` → `ok`
- `KEEP` → `kp`
- `NG` → `ng`

#### CSV Contract
- CSV must contain a `Name` column and may contain `Season`, `Episode`, or both; Season/Episode values must be integers from 1 through 99.
- `Name` matching ignores paths, common media extensions, and letter case.
- BOM, CRLF, quoted fields, commas inside quoted fields, and escaped quotes are supported.

#### Ignored Clips and Partial Results

- A clip whose `media` contains audio but no video is excluded from naming and label writes, kept in the XML, and counted as `ignored`.
- A referenced `.jpg`/`.jpeg` still image with an empty, hyphen-only, or placeholder scene or shot/take is handled the same way. A JPEG with valid logging data is still processed; this rule does not extend to DPX or every image type.
- Document-level DIT, path URL, and resolution normalization still runs, so `ignored` does not mean that the entire XML node remains byte-for-byte unchanged.
- `ignored` alone does not make the result partial. Skipped clips, failed clips, or unmatched CSV entries do; if every clip is ignored, no download is offered.

#### DIT Information
- Automatically adds DIT info: 'Generated by https://double-love.ahua.space'
- Deploy your own instance to modify 😁😁

#### Naming Examples

1. **With Season + Episode CSV data**:
   - Input file: `D_0039C001_240808_050950_a1D0U` (Season: 1, Episode: 44)
   - Output file: `01_44_026_04_01d`

2. **Episode only CSV data**:
   - Input file: `D_0039C001_240808_050950_a1D0U` (Episode: 44)
   - Output file: `44_026_04_01d`

3. **No CSV data (traditional)**:
   - Input file: `D_0039C001_240808_050950_a1D0U`
   - Output file: `026_04_01d`

## 📦 Installation

1. Clone the repository

```bash
git clone https://github.com/Ahua9527/Double-Love.git
cd Double-Love
```

2. Install dependencies

```bash
pnpm install
```

3. Development

```bash
pnpm dev
```

4. Build

```bash
pnpm build
```

5. Run the Web maintenance checks

```bash
pnpm lint
pnpm test
git diff --check
```

## 🔒 Security Notes

- All file processing occurs locally in the browser
- XML files up to 50MB and one optional CSV file up to 10MB; CSV supplies Season/Episode metadata
- One CSV is accepted at a time, with at most 99 accepted XML and CSV files in total; duplicate files are ignored
- `public/_headers` declares CSP, anti-framing, and least-privilege headers for the current Cloudflare Pages deployment; verify the real responses after deployment
