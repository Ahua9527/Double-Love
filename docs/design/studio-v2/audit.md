# Double Love Studio v2 视觉与产品壳差距审计

审计日期：2026-08-21
审计范围：`studio/` React/Tailwind 前端、`src-tauri/` 窗口与命令入口，以及本机可安全打开的 BaoCut 界面。只记录产品界面与代码结构，不记录转录文本、素材内容或用户路径。

## 先说结论

当前 Studio 是一个能进入粗剪工作区的技术原型，不是完整的 macOS 产品壳。最大差距不在“颜色还不够像”，而在于 BaoCut 已经把首次启动、模型选择、设置、诊断和下载状态组织成连续的产品流程，而 Studio 仍把“项目设置”当成唯一设置页，把无项目状态当成一个大面积空白入口。

优先级应按下面顺序推进：

1. P0：补齐全局产品壳（首次启动、独立设置窗口、模型管理、诊断与后台任务），并把全局设置和项目设置分开。
2. P0：建立 760×580 设置窗口的紧凑行式布局；避免当前 1440×900 主窗口中间的大块空白成为默认体验。
3. P1：统一视觉令牌、控件和状态语义，再调编辑器的预览／转录／时间线比例。
4. P1/P2：补齐可恢复的空态、错误、下载、校验、离线和无障碍状态。

## 证据边界

### Double Love Studio 实际界面

- 运行中的主窗口为 1440×900。项目未打开时，侧栏仍占据约 250px，主区只显示“打开一个本地项目后，可以调整画布、字幕和项目历史。”；没有首次启动说明、模型准备状态或新用户下一步。
- 点击“我的项目”后，主区是居中的 Sparkle 图标、标题“从一个本地项目开始”、一段说明和“新建项目／打开项目”两个按钮。空白区域很大，缺少最近项目、模型准备、恢复入口和可理解的状态分层。
- 点击“后台任务”后，主区只有标题、说明和“当前没有后台任务。”一行，没有任务历史、模型状态、失败恢复或继续下载。
- 点击“设置”后，在没有项目时只显示“打开一个本地项目后，可以调整画布、字幕和项目历史。”；这不是全局设置页。

### BaoCut 实际界面

以下为 2026-08-21 在本机安全查看到的界面，不导入本地素材、不发送数据：

- 设置窗口约 760×580，左侧为稳定的分类导航：通用、快捷键、Text styles、本地模型、云端模型、隐私、诊断、关于。右侧是紧凑的标题、说明、分隔线和行式控件。
- 通用页直接呈现主题单选、应用语言、下载位置、恢复上次项目、时间码毫秒、转录稿分区底色、中日韩文本修正和字幕行长度。
- 本地模型页同时呈现默认模型、下载源、存储位置、可滚动模型列表、体积／内存／实时倍率／准确度、安装／下载／删除／更多操作，以及共享的语音活动检测和说话人识别组件。
- 诊断页是短而可执行的状态页：崩溃报告、自动发送开关、日志保留说明和“打开日志文件夹”。
- 新建转录页是清晰的首步流程：Local file／YouTube / URL／Record 三个来源入口、拖放区、口语语言、识别说话人开关、模型搜索与 All／Local／Cloud 筛选、推荐／已下载／下载状态和性能选择。

BaoCut 的项目库和已载入项目编辑器未在本次审计中导入任何本地项目，因此没有把不可复现的私有素材界面当作证据。编辑器部分以下以 Studio 当前代码结构为证据，视觉验收仍需要一份不含私人内容的合成媒体 fixture。

## 优先级差距与可执行规则

### P0 — 信息架构与产品壳

#### 1. 缺少全局设置、模型、引导和诊断四条产品路径

证据：`studio/src/components/Sidebar.tsx:4-18` 的 `StudioScreen` 只有 `library | editor | tasks | settings`；`studio/src/App.tsx:583-586` 只渲染这四个场景；`studio/src/tauri.ts` 只有项目、转录、说话人和导出命令，没有 `preferences`、`model`、`onboarding`、`doctor` 命令。

规则：先定义应用级导航和窗口边界，再做颜色微调。设置必须是独立、可用 `Cmd+,` 唤起的 760×580 窗口；右侧至少有通用、快捷键、默认字幕样式、本地模型、隐私、诊断、关于七页。项目级画布、输出帧率、历史和当前字幕样式继续留在项目上下文。

#### 2. 首次启动没有可跳过的“从下载到第一次转录”路径

证据：`studio/src/App.tsx:207-227` 的新建／打开项目流程直接进入项目库；`studio/src/components/ProjectLibrary.tsx:18-29` 的空态只有两个项目按钮。当前没有首次启动状态、模型推荐、跳过或重新进入引导。

规则：首次启动固定为三步：本地处理边界 → 根据内存推荐模型并显示体积 → 新建／打开项目。允许跳过；跳过后项目库显示低干扰的模型提示；点击转录而模型缺失时打开安装弹层并保留项目状态。

#### 3. 模型下载没有可见的生命周期

证据：`studio/src/App.tsx:585` 的后台任务只持有一个 `task`，任务类型只有转录／说话人；`studio/src/tauri.ts:46-52` 的 `transcribeStart` 只接收一个模型字符串；没有模型清单、依赖、进度、暂停、续传、校验、失败恢复或安装目录 UI。

规则：模型页必须使用固定状态 `not_installed / queued / downloading / paused / verifying / installed / corrupt / failed`，显示体积、内存、依赖和操作；下载任务由 Rust 状态持有，不依赖设置窗口是否打开；失败必须给出继续、重试、查看日志或清理 staging 的动作。

#### 4. 设置窗口和原生菜单没有窗口契约

证据：`src-tauri/tauri.conf.json:9-25` 只声明一个主窗口；`src-tauri/src/lib.rs` 没有 `settings_open`、窗口 label 或原生菜单命令。

规则：主窗口只负责项目／编辑器；设置窗口用固定 label 单例化，侧栏设置和 `Cmd+,` 都唤起同一窗口。窗口间只同步偏好、模型状态和诊断结果事件，不复制项目状态。

### P0 — 布局密度与窗口尺度

#### 5. 当前空态把“没有项目”表现成大面积空白，而不是产品入口

证据：`studio/src/index.css:51` 的 `.studio-library-empty` 使用 `min-height: calc(100dvh - 54px)` 与 `place-content: center`；运行截图中除左栏和中间一组按钮外没有状态层级。无项目的设置页同样只在中央显示一行文字。

规则：主项目库可保留宽松空态，但必须增加最近项目、模型准备、导入／新建主动作和帮助性次动作；设置、诊断、模型页使用紧凑行式布局，不能复用全屏居中空态。空态应有“当前状态 → 为什么 → 下一步”三层信息。

#### 6. 当前设置把全局和项目字段堆在一个长页面

证据：`studio/src/components/ProjectSettings.tsx:41-97` 同一页面混合外观、画布、输出帧率、项目历史和项目级字幕样式；`studio/src/App.tsx:56-118` 主题只写入 `window.localStorage`。

规则：全局偏好使用版本化 `AppPreferencesV1` 和应用数据目录持久化；项目字段只影响当前项目。默认字幕样式明确标注“只影响新项目”，需要“应用到当前项目”按钮，不要隐式改写旧项目。

### P1 — 视觉系统与控件工艺

#### 7. 视觉令牌方向正确，但组件仍是“网页卡片 + 装饰 Sparkle”

证据：`studio/src/index.css:7-24` 使用浅灰画布、白色面板和蓝色强调色；`studio/src/components/ProjectLibrary.tsx:20-22` 使用 Sparkle 作为入口标记；`studio/src/index.css:51,60-61` 大量使用圆角边框卡片和阴影。运行截图中主窗口是浏览器式的白／灰大平面，控件密度明显低于 BaoCut 的原生设置行。

规则：保留中性灰＋单一功能蓝，但去掉无语义的 Sparkle 和重复卡片。容器只有在表达层级或滚动边界时才使用背景／边框；普通设置使用 1px 分隔线的行。图标统一 16px、同一描边重量，图标必须表达动作或状态。

#### 8. 控件语义没有对齐 macOS 设置习惯

证据：`ProjectSettings.tsx:50-58,76-95` 大量使用裸 `input`、失焦保存和自由填写颜色值；`index.css:41-44,63` 统一把所有按钮做成 7px 圆角胶囊式行内按钮。BaoCut 实际设置使用单选、开关、下拉和“更改…”动作组成的行式控件。

规则：布尔值使用原生开关，三选一使用单选组或分段控件，有限选项使用下拉；颜色／数字输入旁边显示当前值和范围，提交后给出同一行的已保存／失败状态。主动作、次动作、文字动作最多各保留一个层级，避免每个区块都出现同样的描边按钮。

#### 9. 编辑器颜色和时间线片段存在装饰性轮换

证据：`studio/src/index.css:55` 让转录段落使用蓝色和绿色边线；`index.css:58` 让时间线片段按 `nth-child` 在蓝、绿、紫三种表面之间轮换。

规则：颜色只表示语义：当前播放头、选中、警告、已完成、不可用。说话人颜色只用于身份标识，不要让片段位置决定颜色。默认编辑器表面保持单一中性灰，选中态使用一个强调色和明确的键盘焦点。

#### 10. 编辑器的代码比例需要用合成素材实测后再定稿

证据：`studio/src/App.tsx:548-572` 采用左预览／右文本、底部时间线；`index.css:53` 固定上半区与底部时间线约 69%／31%，右侧最低 340px；`index.css:54-58` 播放按钮 42px、文本标签 13–14px、片段最低高度 63px。

规则：先用不含私人内容的合成媒体 fixture 做 1440×900 和最小窗口截图，再调比例。预览始终是视觉中心；右侧文本要保证时间码、说话人、当前词和删减态同时可读；底部时间线要有可读刻度、选中／拖拽／裁切反馈，不以固定百分比牺牲窄窗口可用性。

### P1 — 状态、错误和可恢复性

#### 11. 后台任务和通知只有“有／无”两态

证据：`studio/src/App.tsx:579,585` 使用一个蓝色 `.studio-notice` 和一个任务条目；`index.css:45,64` 没有成功、警告、失败、暂停、校验或恢复的视觉分级。

规则：任务列表分为进行中、需要处理、已完成；每项显示阶段、已完成事实、暂停／继续／取消和失败原因。通知用 `aria-live`，按成功／警告／错误使用同一色彩语义，并把恢复动作放在消息旁边；不要只把 Rust diagnostic 原文塞进蓝色横条。

#### 12. 空态没有提供足够的下一步和失败恢复

证据：`TimelinePreview.tsx:84-85`、`MainTrackTimeline.tsx:133-137`、`TranscriptView.tsx` 的状态组件均以短句居中；`index.css:55,58` 只提供基础文字和进度条。没有“模型未安装”“媒体丢失”“校验失败”“下载暂停”“离线运行时不可用”等状态。

规则：每种空态／错误都明确：状态标题、影响范围、下一步按钮、次要帮助链接。下载使用与模型卡同形的进度行或骨架，不使用与内容无关的旋转图标；导入失败保留重试和查看诊断入口。

### P1/P2 — 键盘、VoiceOver 与主题

#### 13. 已有焦点样式，但缺少完整桌面无障碍契约

证据：`studio/src/index.css:31` 只有统一的 `:focus-visible` 轮廓；`Sidebar.tsx:23-34` 有 `aria-label`／`aria-current`，但 `App.tsx:579` 的提示条没有 `aria-live`，拖拽时间线在 `MainTrackTimeline.tsx:153-169` 主要依赖鼠标拖放，应用没有跳到主要内容的 skip link。

规则：为主窗口和设置窗口定义稳定 Tab 顺序、跳到主要内容、VoiceOver label／role／value；时间线所有拖拽动作必须有键盘等价操作；模型下载、校验和错误状态用可读的 live region；焦点环在亮／暗主题都达到可见对比度。

#### 14. 深色主题不是完整的双主题令牌

证据：`App.tsx:56-118` 只保存 `studio.theme`；`index.css:71` 虽有 `.dark` 变量，但编辑器仍有 `#f1f1ef`、`#26282f`、`#e8f4fa`、`#eef8ef`、`#f5f1fc` 等硬编码表面，且通知／选中／片段状态并未全部覆盖。

规则：所有表面、边框、文本、状态色和阴影都来自同一套亮／暗令牌；系统主题切换不改变信息层级。减少动效时保留状态反馈，只去掉位移／缩放动画；设置页的开关、单选和下拉在两种主题都做对比度验收。

#### 15. 全局设置页的隐私、诊断、关于和许可缺失

证据：当前 `ProjectSettings.tsx` 没有隐私、日志、运行时版本、模型许可或第三方许可区块；`studio/src/tauri.ts` 没有诊断或打开日志目录命令。BaoCut 诊断页实际提供了日志保留边界、自动发送开关和打开日志文件夹。

规则：隐私页明确无默认遥测、无音频／声纹上传；诊断页显示 ffmpeg/libass、模型完整性、剩余磁盘和日志目录，并支持路径脱敏的复制报告；关于页显示版本、构建信息、模型／第三方许可。所有“打开目录”动作都只打开本地目录，不在界面中暴露完整私人路径。

## 交付前视觉验收清单

- 先提供 5 张高保真稿：欢迎／首次启动、项目库、编辑器、设置－通用、设置－本地模型；尺寸分别为 1440×900、1440×900、1440×900、760×580、760×580。
- 用合成媒体 fixture 验收编辑器的预览、转录、说话人、时间线、媒体抽屉和导出错误；不使用私人转录或生产素材。
- 设置窗口检查：七页均无占位按钮；每个控件要么改变真实行为，要么明确标为只读信息；`Cmd+,`、侧栏和关闭／重新打开保持同一个窗口实例。
- 模型检查：未安装、排队、下载中、暂停、继续、校验、校验失败、已安装、损坏和删除依赖保护逐态截图。
- 无障碍检查：键盘完成新建、打开、播放、前后跳转、拆分、撤销／重做、导出；VoiceOver 能读出当前页面、模型状态、任务进度和错误恢复动作。
- 亮色、暗色、系统主题、最小窗口和减少动效各做一次截图；确认没有硬编码颜色破坏层级。

## 当前不应做的事

- 不要在现有 `ProjectSettings` 上继续堆全局设置区块；这会把错误的信息架构固化。
- 不要先替换一套新图标或加渐变来“像 BaoCut”；先完成窗口、状态和密度，再微调品牌色。
- 不要用真实生产媒体证明编辑器视觉完成；先建立合成 fixture，再做人工验收。
